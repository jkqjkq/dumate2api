本次同步的改动（15 个文件，按影响面排序）：

  anthropic.js —— **直连通道的原生工具调用（nativeTools），「任务没做就收尾」级**。
    原实现把工具一律降级成纯文本（`[Tool Use: 名字]`），那是**搭子的能力边界**
    （上游不支持 function calling）。但三条直连通道**原生支持**，降级等于把
    tools 丢了。实测对照（同一 TRAE 模型、同一 prompt、同一套 tools）：
      直连上游（只过 buildBody）→ 结构化 tool_calls
          {"name":"Glob","arguments":"{\"pattern\": \"**/*.md\"}"}
      经文本降级路径 → 模型收不到工具定义，正文里吐文本式
          <seed:tool_call><function name="Glob">…（逐字分片到达）
    Claude Code 收到的是普通文本、没有 tool_use 块，于是判定回合正常结束——
    表现为「很快就输出、任务没做」。**不是上游不支持，是这里丢了 tools。**
    Codex 走 /v1/responses，那条路径的 responses.js 一直有 convertTools，
    所以「Codex 用 TRAE 能用工具」掩盖了本文件的问题——两条路径不是同一套代码。
    另修：tool_result 必须各自独立成 role:'tool' 且**紧跟**带 tool_calls 的
    assistant 消息（中间夹一条 user 文本会让上游报「工具结果没有对应的调用」）；
    有 tool_calls 时 stop_reason 必须是 tool_use，**不能照搬上游 finish_reason**
    ——实测 TRAE 给了 tool_calls 却报 `stop`，翻成 end_turn 会让 Claude Code
    认为回合结束、**不去执行工具**。

  traework/chat.js —— 「播报即收尾」的检测 + 一次性重试。
    `Doubao-Seed-Evolving`（reasoning_effort=high）在带工具的请求上有 20~67%
    概率只输出一条进度播报就结束回合，Codex 把「无工具调用」判成任务完成退出。
    实测过五种手段，只有重试可靠（工具名/正文门/tool_choice 都不行）：
      现状 1/5 · 去掉纪律 1/4 · 纪律移末尾 3/4 · tool_choice:required 1/4
      只留一个工具 2/4 · **重试时追加「只输出工具调用」 5/5**
    判据是「模型自己说还有下一步」（无工具调用 + 正文 < 600 字 + 命中
    `下一步|next step`）。**不要放宽成「只要没工具调用就重试」**——真·收尾
    会被逼着再调一次工具，变成永不结束。重试 = 原请求体末尾追加一条 user
    消息（幂等）；重试轮仍无工具就把正文吐给下游收尾，不再重试。
    正文缓冲门：`reasoning_content` 直发、`content` 先扣住、`tool_calls` 一到
    先冲刷正文。**不要改成全量缓冲**——正文总在工具调用之前且只有几十字，
    全量缓冲会把每一轮的流式效果全丢掉。超 DUMATE_TRAEWORK_HOLD_CAP（600 字）
    转直发。`DUMATE_TRAEWORK_REPAIR_RETRY=0` 关闭。
    真机验证：修复前 1~2 次工具调用后停在 8~18%；修复后 17 轮请求、10 次
    修复触发，三章正文（2742/2706/3298 字）+ 台账 + 情欲清单全部落盘。

  traework/index.js —— 流式 usage / finish_reason 补帧 + 工具形状归一化。
    上游的 `token_usage` / `done` 事件此前在流式路径被丢弃，客户端与埋点的
    token 恒为 0、length 截断被当成正常收尾。现按 OpenAI 的 include_usage
    约定补发 `{choices: [], usage}` 与 `{choices:[{delta:{},finish_reason}]}`
    两类帧（三个翻译器都按这两个字段消费）。
    另修：上游的工具调用增量字段叫 `function_call` **不是** `function`
    （`{"index":0,"id":"call_x","function_call":{"name":"read_file",...}}`，
    后续增量里 name 是空串、只有 arguments）。按 `tc.function.name` 取名落空
    → Codex 收到空名工具调用报 `unsupported call:`，随即断流重连 5 次全 502。
    normalizeToolCall() 把三种形状统一，**流式与非流式必须走同一个归一化**。

  qoder/credits.js（新增） —— Qoder 逐请求积分归因。
    Qoder 是三条直连通道里**唯一**由 usage 直接给出本条请求 credits 的
    （`price_factor × tokens/1000`），所以不做游标差值、只按 req_id 落一条。
    千问要读余额差、TRAE 要读 consumed 游标，都只能算「与上一条的差值」，
    第一条没有参照点、并发时还会串账——Qoder 没有这些问题。
    credits 为 null 就**如实留空不落 0**（0 会被读成「这次没花钱」）。
    `since()` 给出账本起点：本功能上线前经网关的请求没有逐笔记录、无法追溯，
    界面必须标出这个起点，否则「合计」会被读成「总共只花了这么点」。

  errtext.js（新增） —— 错误名翻译。
    `aborted` 这类原生错误名对「账号怎么了」没有信息量。存量记录（本功能
    上线前写的）靠这一层也能看懂——lastError 只在成功时才清，一个不再使用的
    账号会永久留着旧串。

  qoder/auth.js —— 手机号脱敏：先剥国家码再切。
    国内号是 86 + 11 位，不剥的话切出来是「861****」而不是「157****」。
    另：phone 落盘时就已是脱敏值（login.js 的 finish 存的），**不再脱敏一次**
    ——对已脱敏的串再切一刀目前碰巧结果相同，但那只是巧合，脱敏规则一改
    就会切出「150********」这种废品。

  model-info.js —— Qoder 模型表补**输出上限**与**免费档**。
    输出上限：上游模型表**没有**这个字段（字段表里只有 max_input_tokens），
    这里给的是网关下发的预算下限，来源标 config——不拿上下文冒充输出上限，
    也不编一个值。免费档：上游 is_free，与 TRAE 的会员折扣是两回事。
    原价倍率（original_price_factor）：错峰/免费模型的 price_factor 会是 0
    （实测 qfmodel=0、原价 0.1），只显示 rate 会被读成「完全不扣费」。
