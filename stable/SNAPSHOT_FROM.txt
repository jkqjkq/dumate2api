本次同步的改动（按影响面排序）：

  qoder/chat.js —— 上游错误必须被认出来，不能再当正常数据转发。
    (1) payloadError 判据收严。上游 provider 层失败发的是
        {"code":"provider_error","message":"All backends failed","type":"provider_error"}
        ——字符串 code 且**首字母小写**，旧判据 /^[A-Z]/ 漏掉，整帧被当正常
        数据转发；翻译器取不到 choices → 客户端拿到 HTTP 200 + 空回答
        （实测 /v1/responses 只发 created/in_progress/completed，output 为空）。
        现在认小写字符串 code、type=*_error、error 对象；同时不误伤
        code=0 / 'success' 这类成功标记。
    (2) envelopeStatus 兜住**非信封的纯错误体**（上游 4xx/5xx 时常见）。
    (3) 首字节超时 DUMATE_QODER_FIRST_BYTE_MS（默认 60s）：上游被限流时
        会接受连接却不回（实测 180s 才 abort），而 600s 空闲超时会把客户端
        拖到早已超时之后。计时从请求写出开始，覆盖「连响应头都不给」的挂起。
    (4) postStream 保留最多 64KB 原始字节，错误时才能把上游 message 如实报出。

  qoder/index.js —— 模型名解析与错误上报。
    (1) **warmupModels()** 预热**每个可用账号**的模型表（缓存按区域+账号
        隔离，只预热主账号会让换号后解析不出模型名）。
    (2) **resolveModelWithFetch()**：热路径上缓存认不出时补拉一次模型表，
        失败退避 60s。此前是纯同步读缓存，缓存为空就把显示名原样当 key
        发给上游 → provider_error → 空回答。
    (3) runOnce 按状态码判 HTTP 错误（流式与非流式两条路径），并从原始 body
        取上游 message；200 但非 SSE 的纯错误体也兜一次信封解析。
    (4) onModel 回调上报**实际发给上游的 key**（埋点 mapped_model），
        名字有没有解析成功不再在日志里不可见。
    (5) 全账号失败时带上每个账号的失败原因；状态码 0（网络层失败）映射为 502。

  server.js —— 三处：
    (1) **补上 Qoder 模型表预热调用点**。此前 server.js 只给千问和 TRAE 写了
        预热块，Qoder 的 warmup 从没被调用过，网关进程里缓存恒为空。
    (2) handleDirectChannel 新增 onModel 回调，把实际模型 key 写进埋点。
    (3) 直连通道的错误统一走 done 回调（单独再调 logRequest 会被去重丢掉）。
