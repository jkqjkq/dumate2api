本次同步的改动（按影响面排序）：

  server.js —— 两处：
    (1) **流式 usage 帧在四个协议入口统一注入**。云端网关
        dumate-svc.baidu.com 只在被显式要求时才在流尾补 usage 帧，而
        stream_options.include_usage 此前只写在 handleAnthropicMessages，
        于是网页凭证链路上「请求全 200、token 全记 0」。现补齐
        handleOpenAIChat / handleOpenAIResponses / handleGoogleGenerateContent。
        注入点必须在 `if (target.direct) return ...` **之后**——直连通道
        （千问/TRAE/Qoder）的 buildBody 不认识该字段。
    (2) **搭子凭证来源默认改为网页池**（router.dumateSource() 返回 web）。
        桌面链路只在 DUMATE_DUMATE_SOURCE=auto 时作为备用参与。网页池
        不可用时给出明确原因，不静默退回桌面凭证。余额游标丢失账号的问题
        一并修掉（points-cursor）。

  reqlog.js —— markFirstToken 从 server.js 私有函数改为此处导出。
    三个协议翻译器（Responses / Anthropic / Google）手里也有 res，此前拿不到
    这个函数，导致 /v1/responses 与 /v1/messages 的流式请求一条
    first_token_ms 都记不下来（实测 dumate /v1/responses 1295 条全为 0，
    而直连通道 1987/1987 正常）。口径统一为「首个上游字节到达」，
    不用翻译器自造的 response.created / message_start 计时。

  responses.js / google.js —— 翻译器的 upstreamRes.on('data') 首句调用
    markFirstToken(res)，与透传分支同一口径。

  fallback-web.js —— 头注释重写：网页凭证**不缺**协议能力（它被包装成伪上游
    响应后由四个处理器原样复用，responses / count_tokens / 前缀分流都照常），
    真正没有 responses 的是 9084 那条独立链路 web-gateway.js。旧注释会让人
    把两件事读混。

  upstream-router.js —— availability('dumate') 新增 web 分支：该通道可用性
    即「网页池里有没有可用账号」。四个协议入口都走这个函数，一处覆盖全部。

  modelmap.js —— /v1/models 只列上游真实模型（model-text /
    model-artifact-validate / glm-5）。claude-* 与 gpt-4o 是客户端协议名，
    别名映射保留、仍可传，但不再出现在可选模型清单里（否则 cc-switch 会把
    它们显示成独立模型）。新增 MODEL_NAMES / displayName()，中文名明确标注
    为本地标注而非上游元信息。

  model-info.js + traework/models.js —— 上下文上限改为显示实测硬限，
    不再拿压缩阈值当上限。

  qoder/session.js + chat.js + index.js —— 从 context_config 取出全部上下文
    档位（200K/400K/1M），默认按**最大档**下发 model_config.max_input_tokens；
    模型名支持上游真实显示名。新增 cachedModels() 供热路径同步读取，
    不额外等一次上游调用。

  traework/constants.js —— 版本码动态生成，上游模型表不再需要手动跟进。

  traework/auth.js —— 新增 lastErrorAt（与 qwenwork/auth.js 同构），
    在 patch() 里集中打时间戳；界面据此显示「N 分钟前」，避免把早已自愈的
    瞬时错误读成当前故障。
