本次同步的改动（7 个文件，按影响面排序）：

  cosy.js（新增）—— **COSY 协议签名算法本体，千问与 Qoder 共用一份**。
    抽出来的理由：两个产品是**同一套协议栈**——同一个 client_id
    （e883ade2-e6e3-4d6d-adf7-f92ceff5fdcb）、同一个聊天路径
    （/algo/api/v2/service/pro/sse/agent_chat_generation）、同一套 Encode=1
    自定义 base64、连服务端公钥都是同一把。算法复制两份必然漂移，
    而这里漂移的代价极高（下面 encode 那个 O(n²) 性能修复就是踩过一次的坑）。
    含 encode / aesEncrypt / rsaEncrypt / md5hex / newSession /
    buildPayloadB64 / signRequest / composeBearer / sortedJson。

  qwenwork/cosy-sign.js（新增）—— **千问的纯本地签名，不再需要官方 wasm**。
    原实现只有 wasm 一条路，理由是「本地自实现的编码会被服务端拒
    （400 Invalid agent chat JSON body）」——那是 2026-09-23 的结论，
    当时还没有 cosy.js（Qoder 通道 10-02 才接入，其算法与参考实现逐字节
    比对过 22 项测试向量）。两个产品既然同协议栈，那份算法直接适用于千问，
    差异只有 cosyVersion（1.1.52 vs 1.0.10）与几个客户端身份头。
    实测：用本模块签名 → gateway.qwenwork.cn 返回 200、19 帧正常出流、
    正文 "OK"、finish_reason=stop、usage 完整；工具调用也正常
    （finish_reason=tool_calls，参数完整）。
    **顺带解决两件事**：(1) 客户端卸载后通道不再直接死（wasm 是客户端
    二进制资产，随卸载消失——用户 2026-10-14 卸载千问办公后即遇到）；
    (2) 不再每请求 spawn 一个 Node 子进程跑 wasm（原实现用 execFileSync
    **阻塞整个事件循环**几百毫秒，qwenwork/index.js 里专门为它设了
    MAX_ATTEMPTS=3 上限）。本地签名是微秒级纯计算。
    官方 wasm 保留为退路：`DUMATE_QWENWORK_USE_WASM=1`。

  qwenwork/bridge.js —— 签名路由：本地优先，wasm 可选。
    `prepareInfer()` 接口不变（上层 qwenwork/index.js 零改动）；
    新增 `useWasm()` / `signer()` 供 /health 与日志如实上报签名方式。

  qwenwork/index.js —— `status()` 上报实际签名方式（新增 `signer` 字段）。
    **本地签名模式下不再探测 wasm 文件**——它没有任何外部依赖，
    探测只会让「没装客户端」被误报成通道故障。

  server.js —— 三处：
    (1) 千问启动日志与 /health 如实上报签名方式（原来是硬编码的 'ready'，
        那是 wasm 单路径时代的写法）；
    (2) **搭子凭证来源开关 `DUMATE_DUMATE_SOURCE=web`**：显式只用网页凭证，
        跳过整个桌面链路（含启动那次约 3 秒的 PowerShell 探测）。
        启动时间实测 3.1s → 0.1s。池子不可用时由路由层给出明确原因，
        且**不静默退回桌面链路**（用户明确要求走 web，偷偷换凭证来源
        等于瞒着他）。/health 的 dumate 段新增 `source`，`ready` 语义随模式变。
    (3) 回落路径的流式转发修复（上一版已同步，此处一并记录）：
        OpenAI 直通分支原先无条件 `upstreamRes.pipe(res)`，而回落返回的是
        **伪上游响应**（EventEmitter，没有 pipe），抛未捕获的 TypeError
        **打挂整个网关进程**。改为 canPipe 判断——真响应走 pipe（保留背压），
        伪响应走事件转发并在 'end' 里自己收尾。

  upstream-router.js —— `availability('dumate')` 新增分支：web 模式下
    这个通道的可用性就是「网页池里有没有可用账号」。放在这里而不是转发层：
    四个协议入口都走这个函数，一处改动全覆盖，且能给出明确原因。

  qoder/cosy.js —— 改为薄封装（算法转发自 `src/cosy.js`），只留 Qoder 特有
    的身份字段、cosyVersion 与请求头。**导出面完全不变**，三个测试全过。
